## Vérification et mise à jour groupée des addons

### Nouveautés

- **Vérification en ligne au démarrage** des addons installés reconnus dans le catalogue. Le bouton **Actualiser** relance l’analyse locale et la vérification des sources.
- Bouton **Tout mettre à jour (N)** dans les pages des addons dès qu’une mise à jour est confirmée, avec récapitulatif des versions, sources et dépendances avant installation.
- Bouton individuel **Mettre à jour** sur les addons concernés et interface disponible en anglais, français et italien.
- Les addons gérés sont comparés à leur révision installée : un changement de fichiers peut être détecté même sans changement du numéro TOC. Les changements concernant seulement un autre addon ne déclenchent pas de fausse mise à jour.
- Les addons manuels reconnus ne sont proposés que si tous les dossiers du pack sont présents et leurs versions numériques sont clairement plus anciennes. Les versions inconnues ou personnalisées ne sont pas devinées. Une installation confirmée adopte le pack comme addon géré.

### Sécurité et limites

- **Aucune installation automatique au démarrage.** Fermer WoW avant de confirmer une mise à jour.
- Les mises à jour groupées sont téléchargées et vérifiées avant un remplacement transactionnel commun : sauvegardes des anciens fichiers, annulation avant application et retour arrière en cas d’erreur de remplacement. Les paramètres `WTF` ne sont pas modifiés.
- Les fichiers sont téléchargés à une révision exacte avec contrôle des tailles et empreintes Git. Les TOC incompatibles, chemins non autorisés, historiques réécrits et baisses de version numérique sont refusés.
- La recherche reste limitée aux **sources GitHub connues du catalogue** : WoWGaming, Chromie Wishlist et LootRolls, sur leur branche par défaut. Elle ne recherche pas toutes les variantes d’un addon sur Internet et n’est pas limitée aux releases taguées. L’archive WoWGaming reste historique.
- Les packs incomplets et les addons absents du catalogue ne sont pas adoptés par la mise à jour groupée. Les dépendances déjà présentes et non sélectionnées ne sont pas remplacées implicitement.
- Les erreurs réseau et quotas GitHub sont affichés dans le bilan et les journaux, sans déclarer les sources inaccessibles à jour. Vérification annulable, limitée à 90 secondes, sans token GitHub requis.

### Installation

1. Télécharger **`ChromieLauncher-0.4.0-win-x64.zip`** ci-dessous.
2. Fermer le launcher, puis extraire **tout le ZIP dans son dossier réservé**, distinct de la racine du jeu.
3. Lancer **`ChromieLauncher.exe`**. Les préférences restent conservées dans les données locales de l’application.

**Windows x64 · .NET 10 Native AOT · Aucun runtime .NET à installer.** Les DLL du ZIP doivent rester à côté de l’exécutable. Le fichier `.sha256` fournit l’empreinte du ZIP.

### Validation

- **125 tests automatisés**, couvrant notamment la découverte des mises à jour, les versions manuelles, les erreurs réseau, l’annulation et le retour arrière des mises à jour groupées.
- Compilation Native AOT et contrôle desktop dans les trois langues, incluant la visibilité et la traduction du bouton de mise à jour groupée.
- Vérification réelle sur GitHub validée en développement avec détection de **Chromie Wishlist 1.2.0 → 1.2.1**, sans installation dans le jeu.

La mise à jour des **addons** est distincte de l’auto-update du **launcher** : le flux signé du logiciel n’est pas encore activé pour la distribution. Télécharger cette version depuis GitHub Releases. L’exécutable n’est pas signé avec un certificat Authenticode ; Windows peut afficher un avertissement SmartScreen. La compatibilité des addons n’est pas testée en jeu. Projet communautaire indépendant, non affilié à ChromieCraft.
